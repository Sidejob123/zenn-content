## 「動いている」は、ゴールではない

Power Automateで最初のフローが動いた日は、ちょっとうれしいものです。毎朝の集計メールが勝手に届く。申請が来たら上長に承認依頼が飛ぶ。手作業が1つ消えた実感があります。

問題が見え始めるのは、その少しあとです。

- 担当者が異動したあと、フローが止まっても誰も原因が分からない
- 「フロー 1」「テスト用」「新しいフロー」という名前のフローが並び、どれが本番か判別できない
- 作った本人に聞いても「たしか、こういう意図で作ったはず……」としか返ってこない
- エラーは出ていないのに、実は何週間も期待どおりに動いていなかった

どれも、フローの作り方が間違っていたわけではありません。**作ったときには必要なかったもの**（名前のルール、説明、エラーの知らせ方、引き継ぎの情報）が、後から必要になっただけです。

この本は、その「後から必要になるもの」を、最初から少しずつ仕込んでおくための実務書です。

## この本の立ち位置

筆者は、大企業でAI・業務自動化の推進を担当しているエンジニアです。本業ではMicrosoft Copilot / Copilot Studio / Power Automate / Dify Enterprise / Azure APIを扱っています。個人でも、記事投稿やSNSの告知を自動化するしくみを動かしています。

この本では、筆者の立場から見た考え方に加えて、**Microsoftが公開している公式ガイダンス**（Microsoft Learnの「Power Automate コーディング ガイドライン」など）を根拠として示します。「筆者がそう思う」だけで終わらせず、読者が社内で説明するときに使える根拠を添えるためです。

:::message
本書の画面名・機能名は、執筆時点（2026年10月）のMicrosoft Learnの記述に合わせています。Power Automateは更新が速いため、細部が変わっている場合は公式ドキュメントを優先してください。
:::

## こんな人に向けて書きました

- Power Automateでフローを作れるようになり、社内で使われ始めた人
- 部署やチームで、複数人がフローを作るようになってきた人
- 前任者のフローを引き継いで、中身が分からず困っている人
- 社内の自動化を推進する立場で、ルールづくりを任された人

逆に、Power Automateを一度も触ったことがない人向けの入門書ではありません。トリガーやアクションの基本的な作り方は、公式ドキュメントや入門書に任せています。

## 全体の構成

| 章 | 内容 |
|---|---|
| 第1章 | 属人化はどこから始まるか |
| 第2章 | 命名規則とテンプレート |
| 第3章 | 作る前に決めておく3つのこと |
| 第4章 | 本番運用でやらかすミスと防ぎ方 |
| 第5章 | 承認フローを現場に定着させる |
| 第6章 | 「成功」なのに何もしていないフローを防ぐ |
| 第7章 | 外部のAI・APIとつなぐときの設計と認証 |
| 第8章 | 棚卸しと引き継ぎ |
| 付録 | コピーして使える設計チェックリスト |

はじめに・第1章・第2章は無料で公開しています。第1章で「何が起きているのか」を、第2章で「今日から始められる対策」を扱います。ここまで読んで役に立ちそうだと感じたら、第3章以降で、設計・運用・引き継ぎの具体的な手順に進んでください。

## 読み方のおすすめ

最初から順番に読む必要はありません。

- **今まさに困っている人**：第4章（本番運用のミス）と第6章（成功なのに何もしていない）から
- **ルールづくりを任された人**：第2章と付録のチェックリストから
- **前任者のフローを引き継いだ人**：第8章（棚卸しと引き継ぎ）から

どの章も、最後に「今日やること」を3つ以内にまとめています。全部を一度に導入しなくて大丈夫です。1つでも始めれば、半年後のフローは確実に読みやすくなります。
