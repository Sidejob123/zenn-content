title: "第8章 棚卸しと引き継ぎ"

ここまでの章は、これから作るフロー、いま動いているフローを読みやすく、止まりにくくする話でした。最後の章では、**すでにたくさんあるフロー**をどう把握し、どう人から人へ渡すかを扱います。

## 棚卸し：まず「何があるか」を知る

### 一覧を作る

属人化したフローへの対策は、存在を知るところから始まります。チームや部署で動いているフローの一覧を作ります。最初は表計算ソフトで十分です。

| 項目 | 例 |
|---|---|
| フロー名 | 営業_日次売上_集計メール |
| 何のためか | 毎朝、前日の売上を営業部に送る |
| 所有者（主・副） | 〇〇、△△ |
| 最後に動いた日 | 2026-10-09 |
| 状態 | 動いている／止まっている／オフ |
| 業務への影響 | 止まると営業部の朝会資料が作れない |
| 説明書の場所 | SharePointの〇〇ページ |

「業務への影響」の列が大事です。すべてのフローを同じ熱量で整えるのは現実的ではありません。**止まったときの影響が大きいものから**、第2章の3点セットや第6章のエラー処理を入れていきます。

### 組織全体で把握するなら

部署を超えて、組織全体のフローを把握したい場合は、Power Platformの管理者向けの仕組みを使います。Power Platform 管理センターでの確認に加えて、Microsoftが提供している管理者向けのツール群（CoE Starter Kitなど）を使うと、環境ごとのフローや作成者の一覧を集めることができます。導入には管理者の権限と準備が必要なので、推進担当やIT部門と相談して進めます。

また、Microsoft Learnのコーディング ガイドラインでは、ガイドラインの多くを組み込んだツールキット（Power CAT Toolkit）で、ベストプラクティスに沿っていないパターンを自動で見つけてコード レビューを行う方法も紹介されています。

### 棚卸しで決めること

一覧ができたら、フローごとに次のどれかに分けます。

| 分類 | すること |
|---|---|
| 続ける・重要 | 共同所有者を足す、説明書を書く、エラー処理を入れる |
| 続ける・軽い | 名前と説明書だけ整える |
| まとめる | 似たフローが複数あれば、1つにまとめる |
| やめる | 使われていないものはオフにし、一定期間問題がなければ削除する |

「やめる」の判断には、最後に動いた日が役に立ちます。ただし、年に数回しか動かないフローもあるので（第4章）、最後に動いた日だけで決めず、業務の担当者に確認してからオフにします。

## 引き継ぎ：人がいなくなる前にやること

### 引き継ぎで渡すべきもの

担当者の異動や退職が決まったら、フローについては、次のものを渡します。

1. **フローの一覧**（担当していたもの全部。棚卸しの表から抜き出す）
2. **所有者の追加**：後任者（またはチームのグループ）を共同所有者に追加する
3. **接続の確認**：前任者のアカウントで作られた接続を使っているフローを洗い出し、切り替えの段取りを決める
4. **説明書**：フローごとの説明書（第2章）。無いものは、引き継ぎの前に4項目だけでも書いてもらう
5. **有効期限のあるもの**：シークレット、証明書などの期限と、更新の手順（第7章）
6. **「たまにしか動かない」フロー**：次に動く時期と、動く前に確認すること（第4章）

### 順番が大事

引き継ぎで一番困るのは、**前任者のアカウントが無効になってから**フローの問題に気づくことです。そうなると、フローの中身を見ることも、接続を直すことも難しくなる場合があります。

引き継ぎは、次の順番で進めます。

```
1. 後任者を共同所有者に追加する（最初にやる）
2. 後任者が、フローを開いて中身を見られることを確かめる
3. 接続を、後任者側（または共有の接続）に切り替える
4. 後任者がテスト実行して、動くことを確かめる
5. 前任者のアカウントが無効になる
```

1と2を最初にやっておけば、仮に途中で時間切れになっても、後任者がフローを開ける状態は確保できます。

### 引き継ぎ用のチェックシート

| 確認すること | 済 |
|---|---|
| 担当フローの一覧を作った | □ |
| すべてのフローに、後任者（またはチーム）が共同所有者として入っている | □ |
| 後任者が、すべてのフローを開けることを確かめた | □ |
| 前任者のアカウントの接続を使っているフローを洗い出した | □ |
| 接続を切り替え、テスト実行で動くことを確かめた | □ |
| 重要なフローの説明書がある | □ |
| 有効期限のあるもの（シークレット・証明書）の期限と更新手順を渡した | □ |
| たまにしか動かないフローの、次の実行時期を渡した | □ |

## 続けるための仕組み

棚卸しと引き継ぎは、一度やって終わりではありません。続けるために、次のような「決まった時期」を作っておくと、忘れにくくなります。

- **四半期に1回**：棚卸しの表を更新する（最後に動いた日、状態、所有者）
- **異動の時期の前**：引き継ぎのチェックシートを使う
- **業務ルールが変わるとき**：影響を受けるフローを、棚卸しの表から探して確認する（第4章）

## 本書のおわりに

ここまで、Power Automateのフローを「自分しか直せない」状態にしないための実務を見てきました。

- 名前とメモと説明書で、他の人が5分で目的を分かるようにする（第1・2章）
- 作る前に、確認・通知・範囲を決める（第3章）
- 本番で起きやすいミスを、最初から入れておく習慣で防ぐ（第4・5章）
- 「成功」なのに何もしていない状態を、失敗として扱う（第6章）
- 外部とつなぐときは、認証と期限と確認を設計に入れる（第7章）
- 何があるかを知り、人が変わる前に渡す（第8章）

どれも、特別な技術や大きな予算が要るものではありません。必要なのは、フローを作るときに「半年後に、別の誰かがこれを開く」と一度だけ想像することです。

巻末の付録に、ここまでの内容をチェックリストにまとめました。社内のレビューや、自分のフローの見直しに使ってください。

## 今日やること

1. 自分（またはチーム）が担当しているフローの一覧を、表計算ソフトで作り始める
2. 一覧の中で、止まったときの影響が一番大きいフローに、共同所有者がいるかを確認する
3. 次の異動の時期を確認し、引き継ぎのチェックシートを使う予定を入れる
