はじめに：Claude CodeをMCPサーバーと組み合わせて、複数人・複数プロジェクトで使う環境を管理している。v2.1.327で `.mcp.json` の設定保護が改善されたのを機に、組織利用での設定管理の考え方を整理した。

**TL;DR**
- v2.1.327で `claude mcp add`・`remove` が他のキーを削除するバグが修正された
- worktreeモードで `.env` が消えるバグも修正された
- `claude mcp add-json -` でトークンをコマンドラインに書かなくて済むようになった

## 背景：組織でClaude CodeとMCPを使うとどこに問題が起きるか

Claude Codeを個人で使う場合と、組織やチームで使う場合では、問題が起きる場所が違う。

個人利用では `.mcp.json` の設定ファイルを自分1人で管理する。設定が変わったら自分で気づける。

複数人のチームで使っている場合、`.mcp.json` を共有のGitリポジトリで管理していることが多い。複数人がそれぞれのローカル環境で `claude mcp add` を実行することがある。その結果が共有リポジトリに反映され、他の人の設定に影響することがある。

## v2.1.327以前に起きていた問題

### `.mcp.json` の他のキーが消えるケース

`claude mcp add` や `claude mcp remove` を `--scope project` で実行したとき、`.mcp.json` にある他のキーが削除されることがあった。

例えば `.mcp.json` にこういう内容があったとする。

```json
{
  "$schema": "https://raw.githubusercontent.com/...",
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp"]
    },
    "filesystem": {
      "command": "npx",
      "args": ["@modelcontextprotocol/server-filesystem", "/path/to/workspace"]
    }
  }
}
```

この状態で `claude mcp add new-server ...` を実行すると、`$schema` や `filesystem` のエントリが消えることがあった。

ログを見ると「サーバーに接続できない」という記録が残り、原因が設定ファイルの壊れだと気づくまでに時間がかかった。

### worktreeモードで `.env` が消えるケース

Claude Codeのworktreeモードを使っている場合（`claude --worktree` オプション）、サーバーを停止したときに `.env` ファイルが削除されることがあった。

`.env` にはAPIキーや認証情報が入っていることが多い。これが消えると、次の実行時に「APIキーが設定されていない」というエラーが出る。タスクスケジューラで自動実行しているスクリプトが突然失敗していた日があった場合、これが原因だったかもしれない。

## v2.1.327以降の変更点

### `.mcp.json` の保護

v2.1.327から、`claude mcp add`・`remove` が `.mcp.json` の他のトップレベルキーを削除しなくなった。`$schema` も他のサーバーエントリも残る。

確認方法：`claude mcp add` を実行した後、`.mcp.json` の内容をGitのdiffで確認する習慣を入れておくといい。意図しない変更がないかをプルリクエストのレビューで確認できるようになる。

### `.env` の保護

worktreeモードでサーバーを停止しても、`.env` などgit-ignoreされているファイルが削除されなくなった。

過去のバージョンで消えてしまった `.env` は戻らない。APIキーを再発行して再設定が必要だ。今後はこのバグの心配はなくなった。

### `claude mcp add-json -`：stdin入力

MCPサーバーの設定JSONをstdinから渡せるようになった。

従来：
```bash
claude mcp add myserver --command npx --env API_KEY=あなたのAPIキー ...
```
この書き方だとシェルの履歴にAPIキーが残る。

新しい方法：
```bash
cat server-config.json | claude mcp add-json -
```
ファイルから設定をパイプで渡す。コマンドラインにトークンが出ない。

または：
```bash
echo '{
  "command": "npx",
  "args": ["my-mcp-server"],
  "env": {"API_KEY": "'"$MY_API_KEY"'"}
}' | claude mcp add-json -
```
シェル変数から展開する書き方。環境変数経由でトークンを渡せる。

注意：この機能はClaude Codeセッション内部では使えない。外部スクリプトやCI/CDから設定を変更する場合の機能だ。

## 組織でのMCP設定管理で整理した3点

### 1. `.mcp.json` はGitで管理してdiffを確認する

`.mcp.json` をGitの追跡対象にして、変更のたびにdiffを確認する。誰かが `claude mcp add` を実行して設定を変えた場合、コミットに記録が残る。

v2.1.327以降は「他のキーが消える」バグは直ったが、設定ファイルをGitで追跡する習慣は引き続き重要だ。意図しない変更の早期発見につながる。

### 2. CI/CDでの設定変更はstdinを使う

CI/CDスクリプトでMCPの設定を変更する場合、APIキーや認証情報をコマンドライン引数ではなく環境変数から受け取ってstdinで渡す設計にする。

CI/CDの実行ログはアクセス権を持つ人が見られる場合がある。ログにトークンが出ないように設計することはセキュリティの基本だ。

### 3. worktreeモードを使うスクリプトは `.env` の再作成手順を持つ

v2.1.327以降は `.env` が消えなくなったが、過去のバージョンで消えていた可能性がある。また、将来別の原因で `.env` が消えることもありえる。

スクリプトのREADMEやセットアップ手順に「`.env` が存在しない場合の再作成手順」を書いておくと、トラブル対応が早くなる。

自動実行スクリプトであれば、起動時に `.env` ファイルの存在確認を入れ、なければアラートを上げる仕組みを入れておくといい。

## 計測ポイント

- `.mcp.json` の変更をGit logで追跡できているか
- CI/CDのログにAPIトークンが出力されていないか（ログの定期的なレビュー）
- worktreeモードのスクリプトのエラーログに「APIキーが見つからない」の記録がないか

## この検証の限界

この記事はv2.1.327のリリースノートと自分の環境での観察をもとに書いた。すべてのMCPサーバー設定のパターンで動作確認したわけではない。

`claude mcp add-json -` のstdin入力の具体的な動作は、動作確認できていない部分がある（確認できていません）。コマンドラインの引数の組み合わせによっては期待通りに動かないケースがあるかもしれない。

## まとめ

v2.1.327での変更は、Claude CodeをMCPと組み合わせて組織で使う場面での安全性を上げる方向の修正が多かった。

`.mcp.json` の設定保護、`.env` の保護、stdinからの設定入力、の3点は、どれもチームで使う場合に影響する変更だ。今回のアップデートを機に、設定管理の仕組みを見直しておくといい。
