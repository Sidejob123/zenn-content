## はじめに

大企業で Power Automate と Power Apps の展開・運用を担当している。フローは現在18本が本番稼働中で、そのうち業務に直結するものが6本ある。

2026年11月11日、Microsoft から Power Platform Monitor の時間単位アラートに関する発表があった。今まで24時間単位だったアラートが1時間単位で評価できるようになる。

この記事では、発表内容を整理したうえで、自分の環境のフローにどう適用するかを考えた過程を書く。

## TL;DR（結論）

- Power Platform Monitor のアラートルールに「Data review period: 1 hour」が追加された
- Cloud flows（成功率）・Canvas apps・Agents など複数のリソースタイプに対応
- 1管理センターあたり最大10件の時間単位アラートルールを作成可能
- 2026年11月20日までに商用クラウドの全環境で Public Preview 開始予定
- 優先度の高い業務直結フローから設定していくのが現実的

## 従来の24時間アラートの限界

今まで Power Platform Monitor のアラートは24時間単位のメトリクスで評価されていた。

例えば、朝9時から11時にかけて社員全員が出勤処理を行う承認フローがある場合、成功率が09:00〜11:00の2時間で下がり始めても、翌日の24時間集計が出るまでアラートが飛んでこなかった。その間、担当者は状況を知らないまま業務が続く。

障害が起きた翌日に気づいて対応する、というパターンが何度かあった。影響を受けた人数は数十人単位で、そのたびに問い合わせへの対応と原因調査が重なった。

「もっと早く気づけたはずだ」という状況を、24時間単位のアラートは構造的に作り出していた。

## 1時間アラートで何が変わるか

新しい設定では、アラートルールの「Data review period（データレビュー期間）」を1時間に設定できる。

1時間ごとにメトリクスが集計され、設定したしきい値を超えたらその時点でアラートが発火する。朝の繁忙時間帯に成功率が下がり始めた場合、最短1時間後には通知を受け取れる。

前述の承認フローの例で言うと、09:00から下がり始めたとすれば10:00の集計でアラートが飛ぶ可能性がある。従来の「翌日に気づく」から「同日の対応時間内に気づく」に変わる。

注意点として、これはリアルタイム監視ではない。「hourly refresh and evaluation are not real-time」と公式に明記されている。設定完了後にデータが蓄積されるまで、評価は始まらない。ネットワーク監視ツールのようなリアルタイム検知は期待しないほうがいい。

## 設定手順

### Power Platform 管理センターでの設定

Cloud flows や Canvas apps などの標準 Power Platform リソースに対してアラートを設定する場合の手順だ。

1. [Power Platform admin center](https://admin.powerplatform.microsoft.com/) にアクセス
2. 左メニューから「Monitor」を選択
3. 製品を選択し、監視対象のリソースを選ぶ
4. リソースペインが開いたら「+ New alert rule」をクリック
5. サポートされているメトリクス（時計マークが付いているもの）を選択
6. 「Data review period」を「1 Hour」に設定
7. オペレーター、しきい値、重大度、通知設定を構成して保存

時計マークのアイコンが付いているメトリクスだけが1時間単位に対応している。すべてのメトリクスが対応しているわけではないので、選択前に確認が必要だ。

### Microsoft 365 管理センターでの設定（Copilot Managed Runtime アプリ）

Copilot Managed Runtime アプリに対してアラートを設定する場合は管理センターが異なる。

1. [Microsoft 365 admin center](https://admin.microsoft.com/) にアクセス
2. 左ナビゲーションの「Apps」→「All Apps」
3. 対象アプリをクリックして詳細ペインを開く
4. 「Monitor」タブを選択し、「+ New alert rule」をクリック
5. メトリクスを選択し「Data review period」を「1 hour」に設定
6. 設定を構成して保存

2つの管理センターは独立したアラートルールの上限を持っている（それぞれ最大10件）。

## 対応リソースとメトリクス一覧

現時点で1時間アラートが対応しているリソースとメトリクスを整理した（公式発表のまま）。

| リソース | 対応メトリクス |
|---|---|
| Cloud flows | Success rate（成功率） |
| Canvas apps | Time to interactive / App open success rate / Data request latency / Data request success rate |
| Model-driven apps | App open success rate |
| Code apps | Time to interactive / App open success rate / Data request latency / Data request success rate |
| Agents | Agent session success rate |
| Copilot Managed Runtime apps | Time to interactive / App open success rate / App session count / Data request latency / Data request success rate |

Cloud flows のメトリクスは現在「Success rate」だけだ。エラー件数の絶対数や、特定のアクションの失敗率などは対象外になっている。今後追加される見込みがあるとのことだが、現時点では成功率の監視に限られる。

Agents の「Agent session success rate」は、Copilot Studio で作ったエージェントの成功率だと考えられる。エージェントを本番運用しているチームには重要なメトリクスだ。

## 企業のフローに適用するときの設計判断

18本のフローすべてに1時間アラートを設定したいところだが、上限は1管理センターあたり10件だ。優先度を決める必要がある。

自分の場合、次の基準で優先順位をつけた。

**最優先（今週中に設定）**
- 承認フロー（社員全員が毎日使う）：成功率が下がると業務全体に影響
- 外部連携フロー（取引先のシステムとつなぐもの）：止まっても気づきにくい
- 財務系のデータ転記フロー：誤りがあると後処理が大変

**優先度中（来週以降に設定）**
- 通知系フロー（遅延は許容できるが、完全に止まると困る）
- レポート自動作成フロー（次の日に気づいても対応できる範囲）

**優先度低（現時点では設定しない）**
- 24時間に1回しか動かないバッチ系フロー（1時間単位のアラートの意味がない）
- テスト・検証用のフロー

しきい値の設定も悩む部分だ。公式には「heavily used flow（頻繁に使われるフロー）と less frequently used flow（使用頻度が低いフロー）では、異なるしきい値を設定する必要がある」と書かれている。頻繁に動くフローは少しの揺らぎでアラートが飛びすぎるので、しきい値を広めに取る必要がある。逆に、たまにしか動かないフローは成功率が1件のエラーで大きく動くため、件数ベースで考えたい場面もある。

最初はしきい値を緩めに設定して、実際にどのくらいアラートが飛ぶか様子を見てから調整するのが安全だと思う。

## 調査で分かったことと誤解しやすい点

設定前に気になった点を調べたので書いておく。

**チャートと通知の「Data review period」は別の設定**

リソースペインのメトリクスチャートにも「Review period」という設定がある。これはアラートルールの「Data review period」とは別のコントロールだ。チャートで1時間表示にしても、アラートルールの評価周期は変わらない。設定は別々に行う必要がある。

**アラートの通知履歴バナーはリアルタイム状態ではない**

時間単位チャートの上部に表示されるバナー（「この時間帯にアラートが発火しました」）は、過去に発火した履歴を示すものだ。現在も問題が継続中かどうかの判断には使えない。あくまで「その時点でしきい値を超えていた」という記録として見る必要がある。

**既存の24時間アラートは変わらない**

Data review period を1時間に変えるのは新規または変更後のルールにだけ適用される。既存のアラートルールは設定を変えない限り24時間単位のままだ。

**権限の要件**

Power Platform 側のアラートは、既存のテナント管理者またはEnvironment管理者の権限で設定できる。Microsoft 365 管理センター側はPower PlatformまたはGlobal管理者が設定できる。新しい権限は不要だ。

## いつから使えるか

公式の発表によると、2026年11月20日（日本時間）までに商用クラウドの全環境でPublic Previewが開始される予定だ。

Public Previewの段階であることは留意が必要だ。機能仕様が変わる可能性があり、SLAについては本番向けサポートと異なる場合がある。設定を本番フローに入れる前に、テスト環境で動作を確認することをすすめる。

「more will be supported in the future（将来的にはさらに多くのリソース・メトリクスがサポートされる）」と公式に書かれている。現時点で自分が監視したいリソースやメトリクスが対象外でも、今後追加される可能性がある。

## この記事の限界

今回の整理はMicrosoftの公式ブログ（2026年11月11日付）の内容をもとにしている。実際に自分の環境で1時間アラートを設定して動作確認は行っていない（Public Preview開始は11月20日予定）。

しきい値の具体的な数値やアラートの誤検知率については、実際に使ってみないと分からない部分が大きい。フローの種類・使用頻度・組織の業務パターンによって適切な設定は大きく変わる。

Cloud flows に対応しているメトリクスが現時点では「Success rate」のみという点も、実運用では物足りない場面が出てくると思う。今後のアップデートに期待している。
