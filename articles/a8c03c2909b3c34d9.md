大企業のPower Platform担当として、Igniteの発表は毎回一通り確認するようにしている。今回（2026年11月）は特に「Delegation limit 10,000件への拡張」「Inline views / Flow Map views（フローの可読性向上）」「Hybrid authoring とMCP servers（人とエージェントの共同開発）」の3点が実務に直結する変更だった。企業展開の観点から整理する。

出典：[Turn AI ambition into real business value with Power Platform（Microsoft Ignite 2026）](https://www.microsoft.com/en-us/power-platform/blog/2026/11/18/turn-ai-ambition-into-real-business-value-with-power-platform/)（2026-11-18）

## 1. Delegation Limit が 10,000 件に拡張：フロー設計の見直しが必要か

企業でPower Automateを展開していると、必ずぶつかるのがDelegation制限。canvas appsでは以前の制限から10,000件に拡張した。

> Canvas apps gain a detachable formula bar, a delegation limit extended to 10,000 items, and a grid container that simplifies responsive layouts.

SharePointリストやDataverseのデータが大量になった場合、以前の上限でフロー設計が複雑になっていた経験がある。「Apply to eachにPagingを入れて...」という設計が必要だったケースがある企業は、今後の設計では選択肢が増える。

確認が必要な点：

- これはcanvas apps（Power Apps）のDelegation制限の拡張で、Power Automateのリスト取得上限とは別
- Power AutomateのSharePointアクションのデフォルト取得上限は引き続き確認が必要
- 既存フローの設計変更は不要（上限が上がっても、既存のPagination設計は引き続き動く）

「これで全部解決」ではないが、今後の新規フロー設計や既存フローの見直し時の判断材料になる。大量データを扱うPower Appsを設計するなら、この変更を念頭に置いて設計するとよい。

## 2. Inline Views と Flow Map Views：複雑なフローの可読性が上がる

Igniteの発表の中で、「地味だが使う機会が多そう」と感じた変更がこれ。

> Inline views in Power Automate cloud flows, along with new Flowchart and Flow Map views in Power Automate desktop, make it easier understand and evolve your flows.

Power Automate cloud flowの設計画面は、条件分岐が多くなるとネストが深くなって読みにくい。Inline viewsで何がどう変わるかは実際に使ってみないと断言できないが、フローの全体像を把握しやすくなる方向性は明確。

企業でフローのレビューや引き継ぎをする場面では効果が出やすいと考えている。特に複数人がメンテナンスするフローでは、設計の意図を伝えるコストが下がることへの期待がある。

Power Automate desktopではFlow Map viewsも追加された。RPAシナリオの全体構造を俯瞰できる機能で、長くなったデスクトップフローのメンテナンスがしやすくなる可能性がある。RPAを多く使っている企業では確認しておく価値がある。

## 3. Hybrid Authoring と MCP Servers：既存フローにAIエージェントを入れる

今回のIgniteで最も注力されていた方向性がこれ。内容を整理する。

> Agents can work on the apps and flows you've built over the years, not just new ones, so your existing investments keep moving forward.

新規作成だけでなく、**すでに動いているPower AppsやPower Automateのフローに、AIエージェントを呼び込んで修正・追加ができる**という方向性。重要な点は：

- エージェントが使えない状況（トークン上限など）でも、人間は従来どおりローコードで作業を継続できる
- MCP servers経由で、GitHub CopilotやClaude CodeなどのAIエージェントがPower Platformの部品を使って構築できる
- エージェントが作ったものは、ローコードで開いて編集・管理・ガバナンスが可能

MCP serversの追加は、Claude Codeを使う開発者にとって直接関係する変更。Power Platform側のMCPサーバーを通じて、Claude CodeがPower Apps/Flowsの部品を操作できる構成が使えるようになる。

企業のIT担当として現時点で確認していること：

- MCP servers経由の開発は、既存のPower Platformガバナンス（DLPポリシー・環境管理）のフレームワーク内で動く設計になっている
- 既存フローを「AIが勝手に変える」のではなく、「人間がAIを呼び込んで一緒に作業する」設計
- Professional developers はGitHub CopilotやClaude Code経由でも操作できる

一方で不確かな部分もある。セキュリティ審査をどのように通すか、既存のPower Platform環境にMCPを導入する際の権限設計はどうなるか——これらは自社の環境で確認しながら進める必要がある。

## 4. プラットフォームの質改善：130件以上のうち65%が既存機能の強化

今回のIgnite発表で印象的だった数字。

> This year we shipped more than 130 new capabilities, and 65% of them focused on improving quality and experience. We also retired 24 features.

130件以上の新機能のうち、65%が品質・体験の改善に使われている。残り35%が新機能。24の機能を廃止した。

企業展開において、機能廃止は影響度確認が必要になる。24機能の廃止リストは公式ブログから確認できる。自社の環境で使っている機能が含まれていないかを確認しておく価値がある。

性能改善の具体的な内容（リリースノートより）：

- canvas appsの新しいコントロールでのパフォーマンス向上
- model-driven appsの読み込み速度向上
- モバイルアプリの起動速度向上
- オフライン同期の信頼性向上（バックグラウンドでも同期が継続）
- canvas appsのcustomer incidents削減

これらは新機能というより、既存ユーザーへのコミットメント。長く使ってきた企業にとっては、安定性と速度の改善は地味だが大きな価値がある。

## 5. 自社環境で確認すること

今回のIgnite発表を受けて、企業のPower Platform担当として確認しておくことをまとめる。

**すぐに確認：**

- 廃止された24機能のリストに、自社で使っているものが含まれていないか（公式ブログで確認）
- 現在のPower Apps/Power Automateバージョンが最新に近いか（機能の有効化に遅延があることもある）

**中期的に検討：**

- Delegation limit拡張を踏まえた、Power Appsのデータ取得設計の見直し
- MCP servers経由のAI開発対応が自社の開発フローに入れられないか
- Hybrid authoringをどの用途から試すか（新規か既存フローか）

**展開前に整理すること：**

- MCP serversを使う場合、既存のDLPポリシー・環境ガバナンスとの整合性
- Hybrid authoringの承認フロー（人間が最終確認するステップをどこに置くか）
- 社内のPower Automate利用者へのアナウンスタイミング（機能追加で混乱が起きないように）

## この検証の限界

今回の内容は、公式ブログ（2026-11-18）の発表内容を企業担当者の目線で整理したもので、実際に自社環境で検証した項目ではない。

Delegation limit 10,000件については、実際にPower Apps画面で設定を変えて挙動を確認していない。公式ドキュメントで機能の詳細を確認してから展開計画を立てることを推奨する。

Hybrid authoringとMCP serversは、Power Platform側とAIエージェント側の両方の設定が必要なため、自社のセキュリティ・ガバナンス審査のプロセスに沿って判断する必要がある。「発表された」と「使える状態になった」は必ずしも同じではない。自社テナントで機能が有効になっているかを確認することが最初のステップ。
