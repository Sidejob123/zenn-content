## はじめに

Microsoft Ignite 2026 が 2026 年 11 月 17 日（月）から 20 日（木）に開催される。基調講演は日本時間 11 月 18 日の未明（現地 11 月 17 日 13:00 CST）予定だ。

企業内で Copilot Studio・Power Automate・Microsoft 365 Copilot の展開を担当している立場から、今年の Ignite で確認しておきたい点と、当日速報を受け取るための準備をまとめた。

この記事は「発表前の予測・準備の整理」であり、発表後は別途速報記事を書く予定。予測は外れることもあるので、事実として扱わず「チェックの優先順位をつける素材」として読んでほしい。

**TL;DR：**
- Autonomous Agent の GA 有無が設計判断の更新が必要かどうかの分岐点になる
- Power Automate のデスクトップフロー関連の発表は RPA 担当者に影響が大きい
- OneNote・Planner 連携のアップデートは今月のロールアウトで既に動き始めている
- 情報収集の一次ソースは「Book of News」と Power Platform Blog
- 発表を受けてから検証・展開判断をするためのチェックリストをこの記事の末尾に置いている

## Microsoft Ignite の位置づけ

Microsoft Ignite は毎年秋（11 月前後）に開催される IT プロフェッショナル向けの大型カンファレンスだ。Google の Next や AWS の re:Invent に相当するもの。

Ignite での発表は「GA（一般提供）」「Preview（プレビュー）」「発表のみ（将来提供予定）」の 3 種類に分かれる。企業の展開担当者にとって直接関係するのは「GA」の発表。Preview は試験環境で確認できるが、SLA や本番利用の推奨はまだできない状態のものが多い。

毎年 Ignite には大量の発表が並ぶが、「Microsoft 365 Copilot」「Power Platform」「Azure AI Foundry」に絞ると、実務に影響する発表を見落とさずにキャッチアップできる。全セッションを追うのは現実的でないため、「Book of News」（Ignite の公式サマリードキュメント）を最初に読む習慣をつけることを勧める。

## 確認ポイント1：Copilot Studio Autonomous Agent の GA

今年の Ignite で最も注目している発表の一つが「Copilot Studio Autonomous Agent の GA」の可能性だ。

Autonomous Agent は、ユーザーがその都度指示しなくても、設定したトリガーや条件に応じてエージェントが自律的に動作する機能。Copilot Studio では 2026 年初頭からプレビューが始まっており、実験的な構成での検証を進めてきた。

GA になると SLA が設定され、本番環境への組み込みが公式に推奨される状態になる。設計判断として「Autonomous Agent を使う前提でフローを組むかどうか」という選択が、GA の有無で分岐する。

確認しておく点：
- 1 エージェントあたりの実行回数・コストの制限はどうなるか
- 人間の承認ステップはどのタイミングで介在できるか（監査対応に直結する）
- エンタープライズ向けのデータ分離・ログ保持の仕様

プレビュー期間中に気になっていたのは、Autonomous Agent が自律的に動いたとき「何をしたか」のログが十分に残るかどうかという点。GA 版でこの点が整理されているかを確認する予定だ。

GA にならなかった場合は、今の「実験的な運用」をもう半年続ける判断になる。それはそれで、設計判断としては明確だ。

## 確認ポイント2：Power Automate のデスクトップフロー（RPA）関連

Power Automate Desktop（PAD）のデスクトップフローは、企業のレガシー業務処理を自動化する用途で広く使われている。Ignite ではここの安定性改善・新機能の発表が毎年複数出てくる。

今年注目しているのは次の 3 点だ。

**実行の安定性改善**：デスクトップフローはクラウドフローと比べて失敗率が高く、エラーが断続的に発生しやすい。フローの再試行ロジックや、失敗時の通知・自動復旧に関するアップデートが今年の Ignite で発表されるとすれば、既存の運用設計を見直す契機になる。

**UI オートメーションの認識精度向上**：画面上の要素を認識してクリックする「UI オートメーション」は、アプリのバージョン更新や画面レイアウトの変化で動作が壊れやすい。画像認識や AI を使った要素検出の改善は、メンテナンスコストに直接影響する。

**ガバナンス・管理機能の強化**：複数のフロー・マシンを管理している環境では、稼働状況の一元監視・実行ログの集中管理が重要だ。管理者向けのダッシュボードや監査ログの機能強化は、コンプライアンス対応にも絡む。

現在運用中のフローに影響が出る可能性がある変更が発表された場合、テスト環境での動作確認を先に済ませてから本番に適用する手順を踏む。

## 確認ポイント3：Microsoft 365 Copilot のアップデート

すでに 11 月のロールアウトで Chat と Cowork の統合が始まっている（別記事参照）が、Ignite ではその先のロードマップが発表されると見ている。

確認したい点がいくつかある。

**Copilot のエージェント連携**：Copilot Studio で作ったエージェントを Teams のメッセージの中から直接呼び出す、といった使い方の範囲が広がる発表が出るかどうか。ユーザー向けの展開説明資料の更新が必要になる可能性がある。

**音声エージェントの GA**：Teams での音声アシスタントがプレビューから GA になるかどうか。会議のリアルタイム文字起こしや議事録生成との連携が変わる可能性がある。コールセンターや対面の窓口業務で Copilot 活用を検討している組織には重要な発表になる。

**ライセンス構成の変化**：Copilot のライセンスは今年に入って複数回変更があった。Ignite でさらなる変更・追加が発表された場合、調達部門との連携が必要になる。ここは即座に動けない部分なので、早めに情報をキャッチアップして社内に共有する段取りをつけておきたい。

## 確認ポイント4：Azure AI Foundry のモデル・機能追加

企業内で独自の AI ツール（RAG システム、カスタムエージェント）を Azure AI Foundry で構築している場合、ここの発表も確認が必要だ。

特に注目しているのは新モデルの追加。o3 系または類似の推論モデルが Azure で正式に使えるようになるタイミングが発表されると、社内 AI ツールの性能向上の判断材料が揃う。

Dify Enterprise のような社内展開型の AI ツールを運用している場合、Azure AI Foundry との連携方法が広がる発表があれば、現在の構成の見直しが必要になるかを検討する機会になる。

新しいモデルが発表された場合の確認手順として、「現在使っているモデルとの互換性」「コスト変化」「既存のプロンプト設計への影響」の 3 点を先に確認する流れが定着している。これを Ignite 後に改めて回す予定。

## 確認ポイント5：セキュリティ・コンプライアンス関連

毎年 Ignite で発表されるセキュリティ関連のアップデートは、IT 担当者にとって見逃せない内容が多い。

Copilot や AI 機能を本番展開している組織が確認しておくべきポイントがある。

Copilot が参照するデータへのアクセス制御の変化は最も影響が大きい。SharePoint や Teams のデータへの検索範囲が変わる可能性がある。機密ラベルが適切に設定されているかを改めて確認するきっかけになる。

Purview（情報保護・コンプライアンス）との連携強化は毎年発表がある。Copilot の操作履歴を監査ログで参照できる範囲の拡張が発表されることが多い。コンプライアンス要件のある組織では追跡が必要な変更になる。

## 展開判断のチェックリスト（発表後に使う）

発表を受けて行動を変えるかどうかを判断するための確認ポイントをまとめておく。

```
[ ] Autonomous Agent が GA になったか（Yes なら本番設計の検討を開始）
[ ] デスクトップフロー関連で既存フローに影響する変更があるか（Yes なら検証が必要）
[ ] Chat/Cowork 統合のさらなる変更があるか（説明資料の更新が必要か）
[ ] ライセンス変更の発表があるか（調達部門への確認が必要か）
[ ] セキュリティ・Purview の変更があるか（監査設定の見直しが必要か）
```

各項目で「Yes」になった場合、テスト環境での確認 → 本番適用の判断 → 説明資料・手順書の更新、という流れで対応する。一度に全部対応しようとすると漏れが出るので、発表のあとで優先順位をつける。

## この検証の限界

この記事は発表前の予測・準備の整理であり、事実ではない部分が多く含まれる。

Ignite での発表内容は直前まで非公開のため、予測が外れることは毎年ある。たとえば「GA になるはず」と予測していた機能が「Preview 延長」になることもある。

記事内で「確認しておく点」として書いたことは、発表後に実際の仕様と照合して判断することが必要。推測で展開計画を変えないよう注意する。

また、このチェックリストは現在の環境構成（Copilot Studio + Power Automate + Azure AI Foundry を組み合わせた大企業向け展開）を前提にしている。構成が異なる組織では確認の優先順位が変わる可能性がある。

発表後の速報は、公式の一次情報（Book of News・各ブログ）を確認してから書く予定。
