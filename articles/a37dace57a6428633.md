本業で Copilot Studio と Gemini Agentspace の両方を触る機会が増えてきた。どちらも「エージェント」として売り出されているが、実際に設計で迷う場面が出てきたので、自分なりの判断軸を整理する。

「どちらが優れているか」という比較ではなく、「どちらを選ぶとどういう場面で詰まるか」という観点で書く。

## そもそも何が違うのか

大きな構造の違いを先に整理する。

**Copilot Studio**
- Microsoft 365 のデータ（SharePoint・Teams・メール・カレンダー）へのアクセスがネイティブ
- IT 部門の管理下に置きやすい（Microsoft Entra、DLP ポリシー、管理センター）
- Power Automate との連携でアクションを定義する
- 承認フロー・社内規程の連携に強い

**Gemini Agentspace**
- Google Workspace（Drive・Gmail・Meet・Docs）との統合
- Vertex AI エコシステムとの連携に強い
- マルチモーダル（テキスト・画像・動画）の処理に強み
- Google 検索との統合で外部情報の参照がしやすい

これだけ見ると「データがどこにあるか」で決まりそうに見える。実際には組織のほとんどが Microsoft 365 を使っているため、Copilot Studio が選ばれるケースが多い。では Gemini を選ぶのはどういう場面か。

## 判断軸 1：ガバナンスの要求水準

大企業で社内向けエージェントを展開する場合、一番最初に詰まるのはガバナンスだ。「誰がこのエージェントを使えるか」「どのデータにアクセスさせるか」「ログをどこに残すか」を IT 部門が管理できるか。

Copilot Studio は Microsoft Entra のグループとロールでアクセス制御ができ、管理センターから一括で DLP ポリシーを当てられる。既存の Microsoft 365 のガバナンス体制をそのまま使えるのが大きい。

Gemini Agentspace も Google Workspace の管理コンソールで制御できるが、両社の製品を並走させると管理コンソールが 2 つになる。IT 部門の工数が増える上、ポリシーの整合性を保つのが難しくなる。

**判断の目安**：組織の ID 管理・ログ基盤が Microsoft 寄りなら Copilot Studio。Google Cloud Platform に大きく投資していて、エージェントの実行ログを BigQuery などに流したいなら Gemini の方が設計しやすい。

## 判断軸 2：既存フローとの接続

エージェントが何かを「する」部分——承認を取る、データを更新する、メールを送る——は、たいてい既存の業務フローと繋がる必要がある。

Copilot Studio は Power Automate のフローを「アクション」として呼び出せる。すでに Power Automate で稼働しているフローがあれば、それをそのままエージェントのアクションに使える。設計と実装の再利用性が高い。

Gemini から外部システムにアクセスするには、Extensions（カスタムコネクタ）か Function Calling を使う。Vertex AI の Agent Builder と組み合わせる前提で設計する場合、Google Cloud のエコシステム（Cloud Run・Cloud Functions）と親和性が高い。Power Automate のフローを Gemini から呼ぶことも技術的にはできるが、回り道になる。

**判断の目安**：既存の業務フローが Power Automate にあるなら Copilot Studio が素直。GCP・Cloud Functions の資産があるなら Gemini が自然な選択になる。

## 判断軸 3：回答の根拠をどこに持つか

エージェントが質問に答えるとき、「何を根拠に答えるか」が設計の核になる。

Copilot Studio は SharePoint のドキュメントを参照先として設定できる（Retrieval Augmented Generation）。社内規程・手順書・FAQ を SharePoint に置いて管理している組織では、そのまま使える。更新も SharePoint 側でやれば反映される。

Gemini は Google Drive のドキュメントや Google 検索（外部情報）を参照できる。社内情報だけでなく、外部の最新情報も参照させたい用途に向く。一方、外部情報を参照できることはリスクでもある——社内向けエージェントなのに外部の古い情報を引いてくる可能性がある。

**判断の目安**：「社内の決められた情報だけを使って回答させたい」なら Copilot Studio の方が制御しやすい。「最新の外部情報も含めて回答させたい」なら Gemini の方が強い。

## 実際に迷ったケース

大企業の IT 部門から「部門内の FAQ ボットを作りたい」という相談を受けた。データは SharePoint に置いてある。ユーザーは全員 Microsoft 365 を使っている。

これは迷わず Copilot Studio を選ぶ。

別のケース：「製品の技術文書（PDF・動画・画像が混在）をベースに、外部のパートナーが質問できるエージェントを作りたい。将来的には Google Meet の録画も参照させたい」という要件だったとする。データが Google Drive にあり、マルチモーダル処理が必要で、外部ユーザー向けなら Gemini の方が合う。

ほとんどの場合は「既存のデータがどこにあるか」「既存のフローがどのプラットフォームにあるか」で 8 割方決まる。両方使っている場合でも、主軸は 1 つに絞る方が運用しやすい。

## 迷う場所はここじゃなかった

「どちらが賢いか」「どちらが精度が高いか」という比較は、実際の導入設計ではほとんど意味がなかった。

使っている LLM のバージョンはどちらも継続的に更新されるし、精度の差は RAG の設計（どんなドキュメントをどう整備するか）の方が大きい。モデルを選んでいるというより、**エコシステムを選んでいる**という感覚が正確だと思う。

「Copilot Studio と Gemini、どちらを使うか」という問い自体より、「誰が管理するか」「データはどこにあるか」「既存の何と繋ぐか」の答えを先に決めると、自然とどちらかに絞られる。
